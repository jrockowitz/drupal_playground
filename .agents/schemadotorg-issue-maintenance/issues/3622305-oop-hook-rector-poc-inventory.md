# Schema.org Blueprints OOP hook Rector POC and conversion inventory

This public research appendix records a disposable Drupal Rector proof of
concept for [issue #3622305](https://www.drupal.org/project/schemadotorg/issues/3622305).
It documents what automation produced, where it failed, and the module-by-module
process proposed for the production conversion.

> Caller counts below are lexical search results. They identify review leads;
> they do not prove that a service or interface is private or safe to remove.

## Recommended conversion process

Convert exactly one production module at a time. Review its complete diff and
targeted tests before beginning the next module. Completed modules may later be
grouped into coherent merge requests, with one reviewed commit per module.

### Per-module definition of done

- [ ] Inventory runtime hooks, callbacks, helpers, services, interfaces, and
  callers.
- [ ] Identify required procedural hooks that must remain procedural.
- [ ] Add or update behavioral and ordering coverage.
- [ ] Implement cohesive `#[Hook]` classes.
- [ ] Use constructor injection with no static `\Drupal` calls in hook classes.
- [ ] Remove converted procedural hooks and all `#[LegacyHook]` wrappers.
- [ ] Preserve public services and interfaces unless a separate API change is
  approved.
- [ ] Determine and record `skip_procedural_hook_scan` eligibility.
- [ ] Rebuild caches and the container, then run targeted PHPUnit, targeted code
  review, and `git diff --check`.
- [ ] Update this ledger and the detailed hook inventory before requesting
  commit approval.

## Proof-of-concept execution

The maintainer authorized a raw, uncommitted Rector conversion of the complete
main project on 2026-09-10. The root `rector.php` was left unchanged. The
standalone upstream configuration was invoked directly because the local
`ddev rector` wrapper always appends the root configuration:

```bash
ddev exec rector process web/modules/sandbox/schemadotorg \
  --config=/usr/local/composer/vendor/palantirnet/drupal-rector/rector-hook-convert.php
```

The normal project configuration was run as a dry run only. It reported three
unrelated files; the sole deprecation conversion was `check_markup()` in an API
documentation example. Those changes were not applied.

### Baseline

- PHPUnit: 280 tests, 4,778 assertions, 245 deprecations, and 538 PHPUnit
  deprecations; passed in 16:47.
- PHPCS: passed.
- PHPStan: 130 existing errors.
- CSpell: passed 923 files with its existing flagged-word configuration warning.
- ESLint: passed.
- Stylelint: 2,464 existing errors.

### Raw Rector result

- Rector reported 61 changed input files, 58 `HookConvertRector` applications,
  and no errors.
- The Git footprint is 111 modified tracked files plus 62 untracked files:
  58 generated hook classes, changed or generated service definitions, legacy
  wrappers, and incidental import normalization.
- Generated code contains 236 `#[Hook]` methods, 236 matching `#[LegacyHook]`
  wrappers, and 189 static `\Drupal` lookups in the generated classes.
- `*.api.php` hook definitions were not converted, but Rector normalized imports
  in two API files and `SchemaDotOrgHtmlHelper.php` because the standalone
  configuration enables import processing.
- Drupal container/cache rebuilding passed.

### Post-conversion verification

- PHPUnit: 280 tests, 4,769 assertions, 1 failure, 244 deprecations, and 538
  PHPUnit deprecations; completed in 14:46.
- New failure: `SchemaDotOrgFocalPointKernelTest::testFocalPoint()` expected
  `image_focal_point` but received `image_image`. Rector moved the
  `focal_point` implementation into the base module hook class using
  `#[Hook(..., module: 'focal_point')]`; the result demonstrates hook-order drift
  that must be addressed in the later manual conversion.
- A focused rerun reproduced the same failure with 1 test and 24 assertions,
  confirming that the ordering regression is deterministic.
- Allowed Formats focused checks passed: 2 tests and 32 assertions.
- PHPCS: 4,194 errors and 429 warnings across 118 files.
- PHPStan: 328 errors, up from 130.
- CSpell: passed 985 files with the same configuration warning.
- ESLint: passed.
- Stylelint: 2,517 errors, up from 2,464.
- `git diff --check`: passed for the root and nested module repositories.
- `schemadotorg_experimental`: unchanged and clean on `1.0.x`.
- After the findings and inventories were captured, the maintainer approved
  discarding the reproducible raw output. The main checkout was restored to a
  clean `1.0.x` on 2026-09-10; the Experimental checkout remained untouched
  and clean on `1.0.x`.
- Closeout verification passed: Drupal caches rebuilt, the focal-point sentinel
  passed with 1 test and 33 assertions, and the two Allowed Formats tests passed
  with 2 tests and 32 assertions. Existing deprecation notices were retained.

### Rector limitations and follow-up classes

- Rector intentionally left 112 install/update functions procedural.
- Rector skipped 24 runtime/helper functions. These include the two
  `hook_module_implements_alter()` implementations, the translation entity
  insert hook, and the mapping-type delete hook; classify these as
  `manual hook conversion`.
- The other skipped functions are form submit/validate/AJAX callbacks,
  allowed-values callbacks, preprocess/after-build callbacks, and procedural
  utilities; classify them as `refactor callback later` or
  `retain procedural-only` according to their registration mechanism.
- Generated class naming, missing strict declarations, service registration,
  translation-trait placement, formatting, static service location, and hook
  signatures all require architectural review before production conversion.

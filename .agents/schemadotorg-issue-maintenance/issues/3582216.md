# #3582216: Breadcrumb schema has item with empty id

## Context

- URL: https://www.drupal.org/node/3582216
- Status: Needs Review; bug report in `1.0.x-dev`.
- Lane: Reproduction and patch review.
- Target branch: `1.0.x`.

## Evidence

- The issue includes `3582216-breadcrumb-schema.patch`, attached to comment #2;
  there is no issue-fork branch or merge request.
- Drupal core maps `internal:` to the special `<none>` path. Its URL string is
  empty even after `setAbsolute()`. Therefore a breadcrumb link made with
  `Link::fromTextAndUrl('Section heading', Url::fromUri('internal:'))` produces
  a JSON-LD `ListItem` whose `item.@id` is `""`.
- Reproduced locally on Drupal 11.4.4 using `ddev drush php:eval`; the generated
  item was `{ "@id": "", "name": "Section heading" }`.
- The submitted patch correctly skips that item and preserves contiguous
  positions, but it tests `$text` before rendering a render-array label and
  does not include a regression test.
- Recommended shape: render the label first, cast it to a string, then skip
  only when `$id === '' || trim($text) === ''`. This preserves a valid label
  such as `"0"`, handles render arrays that render to nothing, and avoids
  emitting invalid JSON-LD.
- The local checkout does not include `web/modules/contrib/schemadotorg`, so
  the module's kernel test cannot be run here without installing the module.
- Verified Needs Review on 2026-07-28 with `drupalorg issue:show 3582216 --format=llm --no-cache`.

## Next action

Add a kernel regression test containing an `internal:` / `<none>` breadcrumb
link, then implement the post-render guard. Human approval is required before
local module installation, code changes, a commit, or any public issue update.
